## 2024-05-24 - High-Frequency State Updates in Animations
**Learning:** Found a severe performance bottleneck caused by a `setInterval` firing every 16ms (60 FPS) to update React component state `setDisplay` for animated number counters. Because four of these components were rendering simultaneously on scroll-in, it led to 4 * ~125 = 500+ unnecessary React renders within a 2-second window. The framework creates a lot of overhead when updating components this fast.
**Action:** When creating high-frequency visual updates that don't need complex sub-rendering (like number counters, simple progress bars, or position tracking), bypass React's render cycle completely. Use `motion/react`'s `animate` function combined with a `useRef` to directly mutate DOM properties (e.g., `ref.current.textContent = value`). This completely eliminates the React render overhead.
